**Verdict: FINDINGS OPEN.** 16 of the 18 confirmed findings have a fix and a tombstone shown red before it and green after. Three things stay open, each an owner decision with a skip encoder (a real test, red when un-skipped, so it becomes a permanent guard once decided):

## What held

The finders tried these and they held:

- R25 containment of reads: absolute, relative and `..`-escaping links, links through in-store directory links to outside targets, links to `/dev/null`, FIFOs in `cur/` and at the root, a store root that is itself a link: no marker leaked, each refused and recorded; `os.Root` refuses escapes in intermediate components.
- Without the opt-in no directory link is followed (`Archive.sbd -> .`, `cur/selfdir`, `cur/updir`): each a terminal gap, n = 1, no loop. With it, loops are stopped by the visited set (one `folder-cycle` info each), and file links out of the store and a link to `/dev/null` stay refused.
- The opt-in is matched by canonical source id; `FollowLinksRefusal` rejects an opt-in naming no input; the job parser strips and checks control characters in it.
- FIFOs: 20,000 FIFOs in `cur/` finish in 0.4 s with info class and exit 0; a FIFO named `Inbox` beside a `.msf` is refused without a hang; a FIFO mbox input without `-copy-first` is refused in 0.1 s.
- Hostile names (newline, ESC, RLO, 250 bytes) never reach the ledger, report, sidecar, last-run record or `index.html` with control or bidi characters (the on-disk output directory name keeps U+202E: the path-portability set's N1, not S2b).
- Stub identity is the constant stub, so a stub cannot share a key with a real message that has a Message-ID; stub supersede is metadata-only and keyed by token and digest; a planted `parser_gen` or digest cannot supersede or hide a real record (`SupersedeUnparsed` acts only on a same-token record that already carries the unparsed label, `Load` drops both fields from any record without it and drops a non-sha-256 digest).
- A stale stub is re-examined once and stamped (`StampParserGen`); the manifest is saved unconditionally, so there is no re-examine-every-run loop locally.
- An older binary beside this one: `parser_gen`, `raw_sha256` and the new gap reasons are additive JSON; an older Incremental run skips a stub, an older Full run re-mints the legacy shape, which the next run of this build re-classes and replaces. The only harm found is S2B-AI2.
- Hashing every healthy message when any stub exists (`HasUnparsedStubs` is archive-wide) costs far less than the parse each local message already gets.
- `covered()`: a PST-era reason on a token whose path is now an mbox or maildir is kept, never closed; the folder-flood guard closes nothing; a folder fault blocks closure of the folder and its descendants; the token-scoped `GapKey` keeps two inputs from sharing a locator.
- Stub text: bounded to 64 KiB of input, cut on a rune boundary, C0 and C1 controls stripped, escaped on the page; the report row has a why and a what to do; no token or path beyond the owner's own reaches the report.
- Without the opt-in a link's target is never touched (`Readlink` only, a lexical judgment); with it, the `Stat` of an out-of-store target is inside what the owner opted into.
- A hung or stalled share: non-goal N8 (the open is `O_NONBLOCK`, the read has no bound). Descriptor and goroutine leaks: 10,000 EIO faults, 2,000 mid-stream faults and an abort mid-folder left the lowest free descriptor unchanged; the walk starts no goroutines.
- `go test -race -count=3` over source, util, state, export, job, app (the local tests), `cmd/mailarchive` and `cmd/mailarchive-gui`: clean.
- A regular file swapped for a directory mid-run is refused after the open, not read. Cancellation mid-folder: abort is checked per entry, per message and per mbox message, and a cancelled walk closes no gaps. The panic wrapper adds no unguarded call.
- Huge or sparse message files: a 512 MiB sparse maildir file peaked at about 3 GiB: conceded in design N9 (the memory bound of whole-message reads), not a finding. 20,000 tiny maildir files: the cost is the export phase, pre-existing.
- Windows: the classifier and `Root` behaviour read from code and Go's sources; a junction is classified as a directory link; the OneDrive file placeholder open under `os.Root` is MA-503's lab case. Unix sockets could not be created in the sandbox; their classification was read from the code.
- The GUI wizard's Yes opts in every chosen folder input, not one (a possible tension with "per input"); noted, not rated.
- Concurrent runs on one archive: S2a's lock path is unchanged by S2b.
- Rulings that stand and were not re-opened: R25 and OR6 (the per-input directory-link opt-in follows directory links only, never file links out of the store), J8 and ESC-1, FC1 to FC3, K2 closed by this slice, MF-S1's frozen replay and the identity rules (J5), MA-503, the S2a items already ruled in rulings 13.20.

S2B-AO5's fix is a pure function of the mode; whether listing a real placeholder folder through the root works is the lab's.
- No real mail, no network. The 10 GB sparse mbox and the 100,000-file maildir were not rebuilt in this round; the bounds are stated by N9 and by the finders' runs.

- Behaviour a reader of the diff should know changed with the fixes: the opt-in follows its links after the plain directories (delivery order differs, content does not); a followed link to a directory of mailboxes is now read (the same exposure OR6 accepts for any followed directory, S2B-AO3); a link or special file with a hidden or index-like name is now a row; an orphan `X.sbd` and the `.sbd` below an empty parent are now read; the sniff accepts a BOM and leading blank lines.
