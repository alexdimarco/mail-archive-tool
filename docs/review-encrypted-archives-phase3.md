**Design:** `docs/design-encrypted-archives-phase3.md`, reviewed at sha256
`80fff82448a1f93c2c6482c3016494934466fdae9c9d95e193dc0a2637898dec` (the first draft, before

**Repository:** branch `encrypted-archives`, commit `00e5fda`.
**Date:** 2026-10-25.
**Gate:** the pre-code design review (`../assurance-kit/process/design-review.md`). The design is
security- and architecture-relevant: it is the first phase that lets a person make, open and
manage an encrypted archive.
**Run:** workflow `phase3-design-review` (run `wf_b4050aa7-fcc`, 9 agents, all read-only):
- Five finders, each taking two adjacent lenses:
  - PUR: 1 purpose, 2 proportionality;
  - DUR: 3 durability, 4 usability;
  - SEC: 5 integration, 6 security;
  - FAIL: 7 failure domains, 8 migration;
  - COST: 9 dependency and cost, 10 honesty.

Grounding was a read-only code map made the same day (workflow `phase3-map`, run

## Verdict

**GO_WITH_CONDITIONS.**

Tallies:
- 92 findings: 77 confirmed, 14 duplicates, 1 refuted (SEC-18).
- Of the confirmed, after the skeptics' re-grading: 1 blocker, 42 major, 34 minor.
- Every confirmed finding maps to a condition below (checked by script).

The one blocker, FAIL-01, was dissolved by the rescue pass (condition 1).
- **The defect:** the Desktop's idle lock, an archive switch or Shut down destroys the
  dashboard's key while a Run now or another job is still using it.
- **The fix:** a lease rule. Each job gets its own copy of the key, made without a key
  derivation by `vault.Open(out, want, vault.KeySecret(k))` (`internal/vault/store.go:242-262`).

The rescue found no deeper blocker. It cautioned that the conditions rewrite three sections
materially: §4 the record, §11 the conversion, §13.2 the program copies. Under the gate's rule
that a material change re-runs the review, condition 44 requires a focused re-review of those
sections (lenses 3, 6 and 7) before the slices that build them (P3-0, P3-5, P3-6) are coded.

What the rescue tried, in its words (summarised):
- the lease rule needs no change to Phase 1's frozen API;
- rotating drives need no volume identity from the operating system ("copy heads" keyed by
  pointer digest fix it; the pinned `x/sys` v0.48.0 has no macOS `getattrlist` wrapper);
- sealing with a pending key before `Commit` is impossible without an API change, so A12's
  roll-forward from `verified` stays;
- a unit larger than the memory budget cannot be opened on that machine, which must be stated
  (COST-06, PARTIAL);
- the download trust chain is a residual to disclose, not a blocker (SEC-08, PUR-08, PARTIAL);
- the lock order is the archive lock before the record lock;
- older writers during a conversion are caught by re-taking the lock at the renamed path.

## Owner rulings on the review (2026-10-25)

The rescue surfaced three items that are the owner's, not conditions the review can impose.
The owner ruled:

- **No scripted keyed backups in Phase 3.**
  - A backup into an encrypted archive needs a person: Desktop's Run now, or the command line
    at a foreground terminal.
  - Keyed `export`/`graph` without one are refused, naming Phase 4.
  - Condition 10 stands as written.
- **The recovery file is offered, in the safer form.**
  - It escrows only the recovery entry.
  - Putting it back needs the recovery key and sets a new password and a new recovery key in
    the same step, so a withdrawn password can never come back.
  - Condition 14 stands. It is built in its own slice with its own adversarial pass.
- **Published releases become unchangeable.** The release process stops replacing a published
  release's files (`gh release upload --clobber`, `.github/workflows/release.yml:69-70`). A
  fix is a new version. That change is made in P3-5.
  - Condition 37 is then simpler: a program copy that differs from its release's published
    checksum is a changed copy.
  - Its disclosure still holds: checksums from the same release prove the files arrived
    unchanged, not who made them.
- Optional, not taken: signing `SHA256SUMS` with a key built into the program (SEC-08) goes
  beyond ruling O1 and stays an owner choice for later.
