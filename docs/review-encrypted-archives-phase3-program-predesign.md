## Conditions (must be folded into the design before code)

1. Confine program/ (SEC-01, INT-01, the blockers). Check program/ without following links (Lstat, the realDir pattern, the §4.5 reparse-tag rule). If it is not a real folder, skip the program step with a warning and touch nothing. Open an os.Root on program/, confirm it is the same file as the Lstat, and do every list, read, remove and rename through it. Remove one entry at a time (never RemoveAll), and only regular files or links whose names match §3. Folders and other entries are reported, never deleted. Tests: a link or junction at program/ pointing at a populated folder ends with that folder untouched; a junction inside program/ is not followed.

2. Validate the sealed set when it is read (SEC-02). Names must match §3 and must not be temporary or reserved names. `version` must be an exact vMAJOR.MINOR.PATCH or empty, and origin and state must be known values. `expects` is validated the same way before it is used as a path.

3. Let the program set change over time (INT-02, INT-15). `program` is its own sub-object with its own `format` number, decoded leniently while the rest of the header stays strict. If it is unknown or fails validation, program/ is left untouched with one warning and the backup goes ahead. It is never coupled to state.ManifestVersion. A pin test covers its fields per format. An absent set means 'not chosen', and the card offers it with O1's wording, already ticked.

4. Each sealed entry carries {name, sha256, size, origin, version, platform, reads} (SEC-05, DUR-14, DUR-02, DUR-01). `reads` is a program-side record-format revision, bumped whenever an older program could no longer open what this one seals; no new header field is needed. program.version becomes the high-water mark of release copies ever sealed.

5. The kept copies must be able to open the archive (DUR-01, FOC-09, the blocker). When this program's revision is higher than what a kept copy reads, it writes its own self-copy beside them under a stated trigger ('the kept copies cannot open this archive'). It warns on every run and in status and the card, and the note names the copies that open the archive. This answers open question 2.

6. Decide per platform, from what is present and verified on disk (DUR-05, PUR-07, DUR-14, FOC-02, INT-06). Release copies are written only from a verified cached version at or above the high-water mark (equal for repairs). A higher copy that cannot be repaired is removed and its entry kept marked missing, with a warning. A missing file that cannot be rewritten gets a warning naming its platform. A self-copy is written for this computer's platform when that platform has no present, verified copy that opens the archive. Another computer's self-copy stays until a release copy for its platform arrives (an upgrade, with no warning). A platform the newer release does not publish keeps its older copy. Requirement 6's list of triggers, and §14's, gain 'the download did not finish within the wait' and 'the kept copies cannot open this archive'.

7. One staged protocol for repairs, upgrades, self-copies and turning keep off (DUR-02, DUR-12, DUR-13, INT-04, PUR-06, DUR-07, FOC-05): (a) stage the incoming files as program/.mailarchive-program-<n>.tmp (encmark tempRe), each synced and re-hashed, with the free-space margin applied to the total; (b) render the new note text from the planned set; (c) an intent commit sealing, per name, both the current and the incoming entry (and any removals), plus both note digests; (d) renames, single-entry removals, the note; (e) a landed commit sealing the set as it now stands and the note digest. While intent stands, a file or note matching either entry is accepted silently; anything else is judged as normal. The program's own temporary files are swept silently. encmark's litter list applies inside program/. Turning keep off removes the folder only if it is empty. §1 is corrected to name the temporary files.

8. The note is written from the sealed landed set (FOC-04, FOC-05, PUR-09, FOC-06, PUR-03, FOC-08, FOC-07, PUR-04). It names each copy by platform and version, with no file names (MA-826), and says which copies can be checked and against which release page. This computer's own copy is marked 'cannot be checked'. Every platform is told to copy the file out of the archive folder before opening or unzipping it. A bare self-copy is written with mode 0755, and the note gives its Terminal steps (copy to the home folder, chmod +x, run). An offline paragraph says: without the release page the copy cannot be checked; anyone who had the drive could have swapped it; changing the password afterwards does NOT undo what a swapped copy took, because the master key is never re-keyed (parent §14). When keep is on but nothing landed, the note says so.

9. Rewrite §3 against the code (INT-03, FOC-07, DUR-07). CheckKeyless walks program/ only and gains an informational field (for example ProgramOdd, a count plus bounded names) that never changes Outcome. It covers links, folders, special files, names outside the pattern and oversize files; temporary files and litter are excluded. MA-743's grammar wording moves to its test row.

10. One hook, held under the lock, with a lasting surface (INT-18, SEC-15, FOC-03, DUR-05). The step runs in Run (local and Microsoft 365, which includes the first backup at creation) after the final Save and before the finalizer, under the archive lock until the landed commit, with the store's generation check. Reindex and pause do not run it. Cancelling ends the step with a warning and leaves the backup's exit code unchanged. The outcome class is recorded in the last-run record (listed in §8's leak budget) and shown as one line in `status` and on the Encryption card. A file missing on two runs in a row becomes a lasting 'incomplete' line.

11. When the download happens (FOC-01, INT-05, FOC-02, INT-06, SEC-08, the blocker). It starts at the BEGINNING of a keyed run, including the first backup at creation, and only when keep is on and the decide step would want this version or the `expects` version. It stays a separate, cancellable task outside any archive lock. The program step waits for it with a stated bound, showing progress, and the CLI process stays alive for it; Ctrl-C or Desktop's cancel skips the wait. When the bound runs out, a self-copy is written under the named trigger. An attempt cut off by exit or cancel is resumed and does not count toward the daily limit. No fetch at Desktop start-up. Open question 3's 'try now' becomes unnecessary.

12. PG5 first, as a release gate (PUR-02, FOC-15, INT-13, PUR-10, SEC-13). Remove --clobber. release.yml creates a draft, uploads every asset and SHA256SUMS, checks them, then publishes. build-release.sh refuses unless every shipped binary (both Linux binaries, both macOS slices, the Windows pair) has Main.Version equal to the tag and vcs.modified=false; this closes SC33, with a catalog row. No tag carrying PG2 until the operator has confirmed immutable releases are on, recorded in the release checklist. §5's claim carries its condition inline, and §5 states its dependency on the build information.

13. Cache robustness (DUR-09, DUR-10, DUR-11, INT-10). One per-user cache lock (lockfile.HoldFile), held by the download, by copies from the cache and by pruning; uninstall refuses while it is held. The cache has a closed shape: versions, assets, SHA256SUMS, verified, expects, the partial-download name, the attempt record and the lock. The uninstall listing lands in PG2. Each asset is synced, then `verified` is written atomically. A failed re-hash deletes the asset and `verified`. `expects` is written atomically; if it cannot be read, nothing is pruned. The download also fetches the `expects` version when needed. Pruning never removes a version used within a stated number of days.

14. A streaming judge (INT-19, SEC-12). Use judgeFile's shape: size first against the sealed size, OpenRegularFile, SameFile, a limited streaming hash. Never read a whole file into memory. Online-only placeholder files are reported 'not checked this run' and are not downloaded again.

15. Refuse scheduling at the chokepoint (INT-07, PUR-05). A typed refusal in schedule.ProgramForSchedule, like ErrTranslocated. Detection: an ancestor folder named program whose parent encmark judges to be an encrypted archive, or a name beginning mailarchive-self-. 'Or a copy of one' is dropped. Tests for each caller (CLI, wizard, Repair, Desktop), plus a Linux release asset outside any archive that still schedules. A keyed run whose own executable lies inside this archive's program/ skips the program step and says so. This lands with PG1 or PG3.

16. How the keep setting is written (FOC-13, INT-17). The card's toggle is an immediate keyed commit under the archive lock, as SealPauseNote does. It is refused, with a reason, when the archive is locked, the drive is missing or a run is under way. The card shows the pending removal until it happens. The CLI gets -program-copies=on\|off on a keyed backup.

17. The Windows self-copy (INT-11). Find it through SiblingQualifies and check it with SameBuild. When it does not qualify, write no self-copy and warn with ProgramNote's words.

18. The keyed check (INT-09, DUR-06). verify -full compares program/ and the note against the sealed set, read-only, and reports a warning-class finding that never changes the mail verdict. Add catalog rows.

19. Honest claims (PUR-08, PUR-01). §8: the download contacts GitHub 'once a day per version until verified, plus the newer version an archive here expects, through the environment's proxy'. Parent §14's matching sentence is corrected to the same words; this is an accuracy fix that the owner acknowledges, not a decision being reopened. §8's swapped-copy bullet states that the check depends on reaching the release page, and names the offline residual, including that the master key is not re-keyed, beside the claim.

20. Fold conditions 1 to 19 into the design. Then re-run a targeted review (lenses 3, 5 and 6) on the rewritten §4 and §5 before PG3 is coded, because the write protocol and the download timing are a material change under the procedure. Record the new digest.
