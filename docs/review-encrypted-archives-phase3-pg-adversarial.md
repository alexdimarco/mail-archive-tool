**Run:** workflow `wf_78433732-a52`. Six read-only finders — SWAP (someone who can write the drive), NET (the
download and the cache), DUR (crash consistency), INT (integration), NOTE (the note and the release gate), FIX (the
P3-4 fix round) — each proving its claims in its own copy; two refutation-default skeptics; one completeness critic.

**Tallies:** 38 found / **32 confirmed** / 2 duplicates / 4 refuted. The critic proved 8 more (CRIT-01..08; CRIT-05, CRIT-07 and CRIT-08 are traps in proposed fixes). By the skeptics' grading one high (DUR-01),
medium SWAP-01, SWAP-02, DUR-02, DUR-05, INT-02, INT-04, FIX-02, and the critic's CRIT-01; the rest low.

The central defect (DUR-01, DUR-02, CRIT-02): the step sealed what it planned, not what it wrote — an upgrade whose
copy failed to stage or to land dropped the earlier copy's entry, and a later run then removed the good file.
**Fixed** by deciding again without what failed, so only what was written lands; CRIT-02's power-cut case stays
an open gap, encoded.

Decided here with high confidence (the owner's standing instruction): CRIT-01 — a downloaded cloud file is a
regular file; CRIT-05 — an unreadable copy is told, never replaced (R4 stands).
