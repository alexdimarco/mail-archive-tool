**Rationale.** What held up in the first walk, unchanged: the happy paths are short and honest (first export of one folder of the configured archive is 9 clicks with the optional folder-list click, 8 without; the first export from another archive folder on a computer with no Microsoft 365 is 8, against the design's "about 9" for section 7.4, with Settings and the weekly backup untouched and the inherited folder byte-identical after load, list, preview and run, read-only media included); the preview says what, how much, where and who can read it; a drive that stops answering mid-export stops the run cleanly (R-o2), survives a restart and finishes in two clicks when it is back; a capture beside an export does not hold it up; the guard asks before a save retargets the weekly backup. What failed was the unplanned road, and the re-walk shows what the fixes did to it. A hard-link or linked-store archive no longer previews clean and then exports nothing: the preview counts the messages the gate will refuse, by reason, says that each will be listed as failed and that trying again will not change it, and says what to do; the card no longer offers a retry that is refused; and the advice, followed, works (OW-10, six of six). An archive that went away is said to have gone away, on every route, and an archive that was merely unreadable is no longer "write-protected". Messages that failed in the moments before an archive vanished are retryable: the 1,200-message walk, which ended "1,152 of 1,200 exported so far" with no button for the other 48, now ends "All 1,200 messages are exported, across the 2 parts of this set". The advice about the search index and about missing files is true for the folder it is about: for another folder it says it is read-only and what can be done, instead of naming a button that cannot act on it. The README an inheritor finds no longer calls the only copy of a message "a convenience made from the original". What did not change: the retry is still bound to the archive's path (F1), the export's names for a folder with no usable index are still `0000-00-00_0000_untitled_<id>` (F14), the whole-folder choices are still lost after 30 idle minutes (F15), and the README and manifest still name every store the archive holds (F8).
