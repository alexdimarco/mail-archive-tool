## Self-review of the fixes

A fix can introduce its own finding; this was one agent checking its own work, so it is weaker than the fresh-eyes check the procedure asks for. One defect was found and fixed (`2e45a9b`): the new scan that finds delimiters and oversized part headers accepted a delimiter line with any ending, where the multipart reader takes CRLF and switches to bare LF only when the first delimiter ends in one; in a message that mixes the two the scan could cut a part out of a place the reader never sees. The scan now keeps the reader's rule; the LF and mixed-ending cases are in `TestAPartHeaderOverTheCapIsNotReadFirst`, and the mixed case was run red against the previous scan. Other points checked: the window onto the parent is verified equal to the bytes the reader returned and falls back to the copy otherwise, so a scan and a reader that disagree cost memory, never content; the scan's delimiter list is capped at `maxParts + 2` entries; a restart after an oversized part cannot loop (the next oversized ordinal is always greater); every change to a note or a label is in the catalog's direction (more notes where the walker differs, never fewer).

## Delegated choices (judgement, recorded)

1. MS2-AC4 is a design-conformant enhancement, rated low by the skeptic, and was built because the bytes are kept nowhere else and it follows the depth and part limits' own shape.
2. MS2-AC7 is fixed as "never show less than v1 in a header field" at the route (after the check passes) and not by changing the strict reader, so the walker's reading is untouched where it reads a value.
3. MS2-AO9's extension bound is 24 runes (a real extension is a handful); a name whose last dotted part is longer is a base, and is cut at 120 runes with it.
4. MS2-AI3 (c) notes the stop only when a part follows it, so a message whose last part is an empty multipart is not marked as having lost something.
5. The four escalations are not fixed because each narrows or contradicts a specified guarantee (design 4.9 wording and counts, design 4.2 step 3a) or moves the frozen identity path (MC28); none was weakened, and no existing assertion was edited.
