# UX contract — mail-archive-tool

Per assurance-kit `process/ux-contract.md`. Numbered X-series consistency
invariants for the CLI, each wired to its enforcement (a catalog MA- row) or
recorded as a condition where the code doesn't yet meet it. X-compliance is
necessary but not sufficient — the friction walk (`docs/review-friction.md`)
stays on top.

| X | Invariant | State | Enforcement / condition |
|---|---|---|---|
| X1 | **Typed exits, named once.** Exit codes come from one declared set. | Partial | Today: `0` ok — including a handled interrupt of a backup (a single Ctrl-C / SIGTERM), which logs "interrupted; progress saved to the manifest" and exits 0 · `1` any error/refusal · `130` / `143` (owner, 2026-10-26) an interrupt (Ctrl-C) / terminate (SIGTERM) that stopped something with nothing saved by it: a stopped check of an encrypted archive (`verify`, design-encrypted-archives-phase3 §8, MA-773) and a prompt of the encrypted-archive verbs (`-encrypt`, the key verbs, a keyed backup's unlock; MA-786, MA-790), each saying it stopped; **widened by the owner, 2026-10-27 (P3-8):** any keyed prompt (`serve`, `search`, `extract`, `reindex`, `decrypt`, the key verbs) and a stopped `reindex -rebuild` of an encrypted archive that saved nothing exit `130` / `143` too. A declined confirmation ("no" to a question) is a refusal: `1`. `repair-record` on a record that needs no repair exits `0`. **`decrypt`** (the unencrypted copy) declares its own set: `0` done · `3` partial · `1` refused · `130` / `143` stopped. Otherwise only a signal the tool does not catch reaches Go's default handler, which the shell reports as 128+signum. Refusals are proven to return non-zero and name the problem (MA-33, MA-34). **`verify`** is the one verb with a semantic result in its exit status: `0` attested (every recorded file checked and intact, none unrecorded) · `2` not attested (any modified/missing/unrecorded file, each named; `unexpected` is reported, not an exit condition) · `1` refusal or error (no manifest, locked archive, unreadable manifest) — declared here and covered by MA-135 (exit 0), MA-136 (exit 2) and MA-140 (exit 1). This `2` is verify's own not-attested signal, unrelated to C1's proposed usage/refusal split. **`extract`** declares its own non-colliding set (PC11): `0` the whole requested set emitted (nothing skipped) · `3` **partial** — some records had no preserved bytes to emit; a FRESH code, distinct from verify's `2`, and the emitted==0 case (nothing extractable, e.g. a PST-only archive) maps HERE, never to `0` and never to an error · `1` refusal/error (no manifest, a `-dest` that equals/sits inside/contains `-out`, a non-empty `-dest` without `--overwrite`, ENOSPC mid-write) — covered by MA-181/MA-182 (exit 0), MA-183 (exit 3), MA-184/MA-185 (exit 1). This `3` is extract's own partial signal, unrelated to verify's `2`. **C1:** split usage/refusal to a distinct `2` from runtime `1`; until then `assure.Refused` asserts `Code(1)`. |
