### J7: is the replacement a weakening?

The old tests (main_test.go at 89c0dc1) pre-bound a plain TCP listener on the `-addr` and called `run(...)`. They asserted: (1) with the port already bound, a normal start returns nil rather than failing to bind, and opens the browser exactly once at `http://<addr>/`; (2) with `-no-browser` it also returns nil and opens none.

The new tests (instance_test.go) start a real instance, then launch a second time on the same account:

- TestDesktopReconnectsWhenAlreadyRunning keeps (1): the second launch returns nil, the browser is opened once more, now by the instance's own opener and at a one-time `/_open?t=` link on the instance's own dashboard (regex-pinned), the second launch itself opens, refuses and shows nothing, and the instance file still names the first instance. It adds what the old test could not: the handoff is made after the instance proves itself with its key, and no second instance starts.
- TestDesktopNoBrowserSuppressesOpen keeps (2) on both the first launch and the reconnect (the instance's opener is not called, the second launch does nothing), and adds the opener-errors path (a fresh link is shown and works) and the "busy" path (two handoffs inside a second open one browser).

What the old tests did that the new ones deliberately do not: treat any bare listener on the address as "the running instance" and open a browser at it. That is the squatter case, ruled J7 and LC-C1, and TestDesktopNeverOpensASquatter, TestDesktopRefusesVisibly and TestDesktopNamesWhatHoldsTheFormerAddress assert the opposite on purpose. It is the reversal of an unsafe behavior by ruling, not an assertion given up.

Evidence that the replacements still bite, by mutation of launch.go (both reverted; the file is unchanged at HEAD): `quiet := false` in handoff makes TestDesktopNoBrowserSuppressesOpen red ("a -no-browser reconnect made the instance open [http://127.0.0.1:.../_open?t=...]"); `case rep.Busy, rep.Opened: return false, nil` makes both red ("a launch while the app runs should reconnect, not fail: MailArchive Desktop is already running for your account but is not responding").

## What held

The finders' attempts that failed to break it, kept so a later pass does not repeat them:

- Mailbox text in the workspace pages: every DOM write uses textContent or createElement (no innerHTML, eval or inline handler); every endpoint answers JSON with nosniff and no-store; mailbox strings reach only JSON string fields and refusal text, never a header, a Location or an href other than the https-checked device URL.
- Selection handles and preview ids: random 8-character handles resolved through a per-session seen-set (R-j2 across sessions and signers); folder ids only from the cached tree; picks plus exclusions bounded at 10,000 and the body at 1 MiB (R-j, never a bare 413); a preview id is spent by Start (R-k on reuse), with its 30-minute TTL, the signer (R-l, R-b) and the slot (R-m) checked.
- Open folder: no path from the request; the recorded root is confirmed by run id and identity; the argv is built only from that root, with no shell; the root is absolute so no argument starts with `-`. The one residual is EW-AI7.
- Browse and Create folder: one dialog at a time and refused while an export runs; the title is bounded and reaches osascript as JSON data; Create folder makes one mkdir through the handle its checks opened and refuses names SanitizeSegment would change.
- Settings: UpdateSettings reloads under the process-wide lock and writes only the caller's fields, so a racing start cannot write back a stale Out (MA-524).
- Sign-in slot: the device code and URL come only from the guarded signin-status POST; a verification URL becomes an href only if it starts with https://; a sign-in as another account drops the session and stops a live run with R-z.
- Hostile names at the writer: stems are timestamp + slug (letters, digits, `.`, `_`, `-`) + a SHA-1 of the Graph id; folder names go through ExportSegment (reserved device names, bidi controls, separators, NUL, controls and blanks all neutralised, 255 bytes); sibling FoldKey collisions, 8.3 aliases and month-directory collisions are disambiguated.
- Graph misbehaviour: nextLinks pinned to the client's scheme, host, port and path; off-host redirects refused before the bearer is sent; 64 MiB page cap; lying Content-Length bounded; truncated bodies retried at most 5 times; 401, 403, 404, 429 and 5xx classified, with the 403 control request and the no-progress breaker.
- Written files: README, manifest and sums are built from the run record, never from the destination; JSON is escaped and control-stripped; SHA256SUMS paths cannot hold a newline or backslash; 1,000 files per directory; final placement is a handle-relative no-replace rename on every OS, and all run-time writes go through the root opened on the folder the run created (the finishing path was the exception, EW-AI1).
- Outside web page (DNS rebinding, CSRF, cross-origin): every workspace and export route is registered through d.api (POST only, GuardLocalPOST, body cap, no-store, panic recovery) behind the C1/C2 session; no route answers without them; the R-y epoch branch reveals nothing.
- Start's own destination handling: one os.OpenRoot, identity compared on the handle, mkdir through the handle, the path and identity checks rerun (K5); a swap after the handle is open still writes into the originally confirmed folder.
- A subdirectory swapped for a symlink that leaves the root is refused by os.Root ("path escapes"); a planted README, manifest or SUMS during a normal run fails the no-replace place and finalization stops with the marker kept; in Finish as partial, Replace swaps the directory entry, so a planted link at that name is not written through.
- Check and finish and Check this export cannot be fooled by a re-hashed SHA256SUMS.txt: sha256(on-disk SUMS) must equal the fingerprint the app reads from the state-dir record or ledger, never from the folder.
- Modes: temp files, finalization files and the marker are 0600, directories 0700, no chmod; state-dir files 0600 and the directory 0700.
- Concurrency: go test -race on the six packages passes; write order SUMS, seal line, ledger line, marker removal, journal end holds under a kill at W9, W9a, W9b and W10; lock order ledgerMu then journalMu is consistent; the process-lifetime context carries the Graph session, token source and every run; two Starts at once give R-m; the breaker uses boot-time clocks so a suspend is a gap, not counted.
- Not filed, noted: the reaper's `release()` writes sess.seen under sess.mu while handlers read the field without it (a formal data race, one pointer read, not seen by -race in 4,000 interleaved requests); the state directory is not fsynced, so a power loss right after W3 can lose the new record's directory entry while the marker exists in the destination (an orphan with a marker the page cannot finish); a message that 5xx-es for ever with /me healthy is bounded only by the 2 h per-message awake bound, which is the design's.

## Escalations

Both need an owner decision, and neither was fixed.

- **EW-AI4** (medium, Windows second logon session of one account). The instance lock is per Terminal Services session, the state directory per user, and nothing records that a run is live in another process, so a second engine reconciles the first one's running export as interrupted and offers Finish as partial. The overwrite half is fixed (record, journal and ledger appends now go to the end of the file, EW-AC1). The rest needs a liveness lock per run (held by the engine for the length of a run, probed non-blockingly by reconcile and the launch sweep) and a new observation ("running in another session of this account") whose wording and card actions are not in the design's §7.6 or ux contract. Skip encoder: TestCopyExportSecondProcessDoesNotAdoptALiveRun (MA-448, R29, R5), whose body is the assertion the fix must satisfy (red today with the Skip taken out: "a second process reconciled a LIVE run as {...
