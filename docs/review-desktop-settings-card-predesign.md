## Why GO_WITH_CONDITIONS and not NO_GO

The owner's three rulings and the design's basic shape still stand: one editor (Settings), the
kind judged by the archive's own record, and one writer of the job file. The 63 findings come
down to about a dozen root causes. For each HIGH finding, a finder named a modest change and the
skeptic confirmed it. None of those changes needs a re-design.

The heaviest root is C-1. Ruling 2 cannot work while the existing kind guard treats "Microsoft
365 is set up and this is the current folder" as proof that a capture is scheduled
(`internal/desktop/kindcorroborate.go:36-41`, proven). Changing that guard is a security-guard
change that the code marks for the owner to ratify (`internal/schedule/schedule.go:641-644`).
So it becomes owner ruling OR-1, and slice 1 waits on that ruling.
