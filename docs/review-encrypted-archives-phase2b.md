## Verdict: **GO_WITH_CONDITIONS**

The central choice holds — one root pointer committing the manifest, history and index by one rename,
a keyless inventory beside it as the F12 anchor — but the draft had real holes, chiefly in what happens
around the edges of a commit: the first run, a lost or stale inventory, a restore, a crash between
writes, Windows, and backup tools copying a live archive. All are folded into the design as P2b-C1..C24
(its sections cite them).

**The rescue's hidden finding (folded as P2b-C10).** No lens saw it: the pointer and the top inventory
file keep fixed names, are rewritten at every commit of a run with the same size, and took the run's
start as their mtime. Mirror-style backup tools that decide by size + mtime (rsync's quick check,
robocopy /MIR) would then skip a changed pointer while mirroring the deletes of the chunks it replaced
— a backup copy naming chunks that no longer exist. Fixed by giving those two files run start + 2 s ×
the commit number, and by deleting nothing during a run (P2b-C9). Not run live against rsync or
robocopy; taken from their documented quick-check behaviour.

**The spike (folded as P2b-C15, C24).** The design's index route works on the pinned driver with no file
written: a read-only one-file in-memory VFS, `NewRestore` into `:memory:`, `Serialize` to capture; the
real `Index.Add` per-row savepoint path (F49) works under `journal_mode=MEMORY`. Confirmed by experiment:
`Deserialize` is unsafe at v1.38.2 (the child process died with SIGSEGV in SQLite's realloc);
`journal_mode=OFF` corrupts the FTS5 index on `ROLLBACK TO`; a WAL-header image does not load as bytes;
peak memory is about 3× the image while sealing and 2× while loading (120 MB image, 20,000 messages,
macOS arm64 only). The spike test itself was not kept (it had no covers marker); a reference copy is in
the session scratchpad for slice 2b-3.

## Fold verification (2026-10-25)

One read-only agent checked every confirmed finding against the first folded revision, the rescue's
changes and A1–A25, and the code at the cited sites. It found 60 of 64 folded faithfully and five
things wrong as written, all fixed in the committed revision:
1. The relative LastSeen encoding re-sealed nearly every bucket per Microsoft 365 commit — a new
   record's LastSeen is its export time (exporter.go:661, :725), not the run stamp, and checkpoints land
   mid-walk. Now: a per-mailbox `seen_at` advanced only at a walk's end (graph.go:418), plus a
   `captured` marker (P2b-C12).
2. The immutable-shard sweep would have deleted the live inventory shards (the inventory never lists
   itself). Now `inventory/` files are kept when the top file names them (P2b-C6, C9).
3. The F12 table had no row for an inventory older than `inv`. Added: refuse (P2b-C7).
4. Verify would report a swept `retained` entry as damage. Now only `live` entries count (P2b-C17).
5. Verify marked a clean restore `restored_older` while the run accepts it. Now `not_attested` unless a
   merge signature is present (P2b-C8, C17).
And fifteen wording gaps, also fixed: the inventory's newer-format gate and the re-seal-on-format-bump
rule; a damaged-shard rule that is not a permanent refusal; residual (3) for I = P + 1 on FAT/exFAT and
its two-cause wording; the mirror's digest in the top file and its write-failure rule; grammar temps in
`inventory/` and the fan-out cap; re-sealing a section loaded from its second copy and the source of the
restore date; "indexing on" for the catch-up; the new `inventory_failed` kind; history header copies
counted once; mtimes that never repeat across runs; test 7's rebuild source; the memory budget versus
2a's attachment peak; the envelope written first in the first commit; plaintext history and index
until their slices; and the F12 encoder's restore list, which must include the pointer mirror.

## Calls made by the author, open to the owner's veto

- **Leak budget (P2b-C20).** Chunk sizes show whether search indexing is on and roughly how big the index
  is, and history chunks (which only Microsoft 365 archives keep) suggest the source kind. The design
  discloses this instead of padding every chunk to one size (about 25% more disk and upload). It sits
  inside A6's frozen residual ("file sizes, file count, timestamps"); two lens findings asked for an
  owner ruling, the skeptic judged it within the residual.
- **Manifest mirroring (P2b-C5).** Every manifest chunk is written twice — double the manifest's bytes
  per commit — because in an encrypted archive a damaged bucket would make its messages unreadable even
  though their content is intact.

## Owner question recorded, not blocking 2b

- Phase 3 needs a confirmed "continue from this older copy" action before RecordedGen is persisted
  (P2b-C8): what it is called, what it warns, and whether it discards the files the older copy does not
  name.
